<CardGrid stagger>
	<Card title="An account per person" icon="seti:lock">
		Local passwords, single sign-on with any OpenID Connect provider, or both. Each account has its
		own fuseraft home, so its sessions, chats, memory, schedule and model profiles are its own.
	</Card>
	<Card title="Sessions and chats" icon="laptop">
		Start multi-agent orchestration sessions and watch every turn and tool call stream in. Chat
		with the same engine as `fuseraft repl`, confined to a workspace.
	</Card>
	<Card title="Approvals in one place" icon="approve-check">
		Every command, file write and handoff your sessions, chats and daemon tasks wait on, with a
		diff for file writes and a badge count in the nav.
	</Card>
	<Card title="Daemons on other machines" icon="rocket">
		Attach to `fuseraft serve` over TLS, send it tasks and answer their approvals. Admins choose
		who may use each daemon, and a read-only token makes one watch-only.
	</Card>
	<Card title="Restarts don't end work" icon="random">
		Sessions and chats run in relay processes that outlive the server. Restart or upgrade
		fuseraft-web and the next one picks everything back up, approvals included.
	</Card>
	<Card title="A wire protocol, not a library" icon="puzzle">
		fuseraft-web runs the `fuseraft` CLI and speaks its versioned wire protocol, so a fuseraft
		upgrade can't break its build, and a mismatched version is reported, not misread.
	</Card>
</CardGrid>
